# سلوكي — المرحلة 3

## ما تم تنفيذه
- صفحة `students.html` لرفع الطلاب من XLS/XLSX بالسحب والإفلات.
- نموذج Excel رسمي من 9 أعمدة:
  1. الرقم القومي
  2. كود الطالب
  3. اسم الطالب
  4. النوع
  5. الصف
  6. القسم
  7. الفصل
  8. رقم التليفون الأب
  9. رقم تليفون الأم
- قراءة الأرقام الحساسة كنص، وفحص الرقم القومي 14 رقمًا، ومنع التكرار.
- فحص كود الطالب، الاسم، النوع، الصف، القسم، الفصل، ورقم الأب/الأم.
- مقارنة الملف الحالي مع البيانات الموجودة: جديد، متغير/منقول، منسحب، بدون تغيير.
- الانسحاب لا يحذف الطالب ولا سجلاته؛ يتم `is_active=false` و`status=withdrawn`.
- جداول سجل الاستيراد.
- إعداد رقم WhatsApp Business لكل مرحلة مع فصل الرقم المرئي عن أسرار API.
- Edge Function مبدئية للإرسال عبر Meta WhatsApp Cloud API، مع وضع محاكاة عند عدم ضبط التوكن.

## التشغيل السريع للاختبار المحلي
افتح `students.html` عبر خادم ملفات محلي (لا تفتحه مباشرة بـ file:// إذا منع المتصفح بعض الموارد).
بدون مفتاح Supabase صالح تعمل الصفحة في وضع Demo محليًا.

## ربط Supabase
1. طبّق `sql/phase-3.sql` في Supabase SQL Editor.
2. راجع سياسات RLS ومواءمة `stage_id` مع جداول المراحل الموجودة لديك قبل الإنتاج.
3. تأكد من `js/config.js` يحتوي على `SUPABASE_URL` و`SUPABASE_ANON_KEY` الحقيقيين.
4. لإرسال WhatsApp فعليًا، انشر `supabase/functions/send-whatsapp/index.ts` واضبط سر `WHATSAPP_ACCESS_TOKEN` على Edge Function، ثم أدخل `phone_number_id` لكل مرحلة.

## سيناريو اختبار المرحلة 3
راجع تعليمات الاختبار في رسالة التسليم الخاصة بهذه الحزمة.

## إصلاح Phase 3.1 (أرقام التليفون)
تم إصلاح تحويل أرقام الموبايل المصرية. كانت الدالة تضيف `2` بدل `20`، فكل الأرقام التي تبدأ بـ `01` كانت تُرفض.
الآن الأرقام مثل `011xxxxxxx` و`015xxxxxxx` تُقبل بعد التحويل الصحيح إلى `201xxxxxxxxx`.
