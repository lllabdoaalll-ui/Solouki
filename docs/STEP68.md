# STEP 68 — Solouki as the single source of truth for teacher behavior reporting

## الهدف
تهيئة الربط بين Grade System Pro وSolouki بحيث لا ينشأ في نظام الدرجات كتالوج مستقل للمخالفات.

## ما تم تنفيذه
- إضافة Edge Function باسم `teacher-behavior-catalog`.
- الدالة للقراءة فقط؛ لا تسجل مخالفات ولا تعدل أي بيانات.
- المصدر الوحيد هو جدول `violations_catalog` الموجود في Solouki.
- تُرجع المخالفات النشطة فقط، مع الكود والوصف والدرجة.
- تُرجع كذلك أماكن الرصد النشطة من `violation_locations`.
- الوصول محمي بسر `TEACHER_BEHAVIOR_BRIDGE_SECRET` ولا يجب وضع السر داخل المتصفح أو Grade System Pro.
- لا توجد أي تغييرات على سجلات الطلاب أو المخالفات في هذه الخطوة.

## الاستدعاء المتوقع لاحقًا
سيستدعيه خادم/Proxy خاص بـ Grade System Pro، وليس متصفح المعلم مباشرة، باستخدام:

`x-solouki-bridge-secret: <server-side-secret>`

النتيجة تتضمن:

- `source: "solouki"`
- `read_only: true`
- `violations[]`
- `locations[]`

## لماذا هذه الخطوة قبل تسجيل المخالفة؟
حتى لا يستطيع Grade System Pro إنشاء أسماء أو أكواد مخالفة مختلفة عن كتالوج Solouki. في الخطوات التالية سيُسمح للمعلم باختيار مخالفة من هذا المصدر فقط، ثم يرسل التسجيل إلى Solouki بعد استكمال التحقق من هوية المعلم ونطاقه وصلاحيات الرصد.

## لم يتم بعد
- استيراد دليل المعلمين والفصول.
- إعداد تشغيل/إيقاف رصد المعلمين حسب المرحلة.
- API تسجيل المخالفة/التكريم.
- واجهة Grade System Pro للرصد.
- WhatsApp والتنبيهات والطباعة.

هذه العناصر ستنفذ في خطوات مستقلة حتى تكون كل نسخة ZIP نقطة انطلاق قابلة للرجوع إليها.
